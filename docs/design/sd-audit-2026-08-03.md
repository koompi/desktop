## 1. What the audit found

### Fixed during the audit (verified on screen)

**The bar came up light on a dark desktop.** Two independent faults in one
chain, both now fixed:

1. `~/.config/systemd/user/xdg-desktop-portal.service.d/koompi-remotedesktop.conf`
   pins `XDG_DESKTOP_PORTAL_DIR=%h/.local/share/koompi/portals`. That variable
   makes xdg-desktop-portal read `.portal` files **only** from that directory.
   It holds `gtk`, `hyprland`, `koompi`, `kwallet`, `gnome-keyring` — a
   Hyprland-era whitelist. `otto.portal` lives in `/usr/share` and was
   therefore invisible, so `otto-portals.conf`'s
   `org.freedesktop.impl.portal.Settings = otto` named a backend xdp did not
   know, and it fell through to gtk, which answers `color-scheme = 2` (light).
   A curated portal directory silently breaks every session whose backend is
   not in it.
2. `org.freedesktop.impl.portal.desktop.otto.service` declares
   `SystemdService=xdg-desktop-portal-otto.service`, and **no such unit exists
   anywhere in the Otto tree**. On a systemd box D-Bus refuses the activation
   with `unknown unit`. This is an upstream bug affecting every Otto install
   with systemd, not just ours.

After both fixes `ReadAll` returns `{'color-scheme': 1, 'icon-theme':
'Adwaita'}` from the otto backend, and otto-bar comes up dark. The live box
carries a hand-made unit in `~/.config/systemd/user/` and a symlink in
`~/.local/share/koompi/portals/` — **neither is in a repo yet.** Task P0-1.

The earlier `theme_scheme` TOML-scoping bug (bare keys swallowed by the last
`[[exec_once]]` table) was fixed the same day and is confirmed good:
`org.otto.Settings.GetColorScheme` returns `1`.

## 2. The macOS-parity brief

Rithy's call: **KOOMPI Otto is the macOS-familiar half of the desktop, and it
should be as good as macOS or better.** That is a design constraint, not a
slogan, so it gets a concrete reading:

- **Menu bar is the app's menu.** A Mac user's first move is the menu bar.
  Ours is an app name and dead space. This is the single largest gap (B).
- **One pointer language.** macOS cursors, one size, everywhere, including
  XWayland and the login greeter.
- **Chrome that agrees with itself.** Bar, dock, window frames, dialogs and
  apps all dark or all light, switching together.
- **Gestures that feel continuous.** Otto already has three- and four-finger
  gestures; what is missing is that they track the finger rather than fire on
  a threshold.
- **Nothing that looks like a Linux desktop leaking through** — no light
  Breeze dialog on a dark desktop, no generic gear icon, no missing dock.

Where macOS should be beaten, not copied: real workspaces per monitor (Otto
already has them), a global menu that also works for GTK apps, and a tiling
half-snap that macOS still does badly.

## 3. Plan

Priorities are by what the desktop cannot be used without, not by effort.

### P0 — the session is not trustworthy until these land

**P0-1. Make the portal chain survive a reboot.** *(fix proven live, needs to
land)*
- `koompi/otto`: add `components/xdg-desktop-portal-otto/xdg-desktop-portal-otto.service`
  (`Type=dbus`, `BusName=…desktop.otto`, `PartOf=graphical-session.target`) and
  install it from the PKGBUILD to `/usr/lib/systemd/user/`. Send it upstream —
  it is a plain bug.
- `koompi/desktop`: stop the Hyprland `XDG_DESKTOP_PORTAL_DIR` whitelist from
  starving other sessions. Cheapest correct fix: have whatever provisions
  `~/.local/share/koompi/portals` symlink every `/usr/share/xdg-desktop-portal/portals/*.portal`
  into it rather than hand-pick five. That directory is provisioned outside
  this repo — find its owner first.
- Regression check that belongs in `tests/`: assert the portal answers
  `color-scheme = 1` under a dark config.

**P0-2. A bar on every output.**
`otto_kit::AppRunner` needs to bind each `wl_output`, create one layer surface
per output, and handle hotplug (`wl_registry` global add/remove). otto-bar then
keeps per-output state for the hug and the full-width fit; the clock and tray
are shared, the app menu follows the focused output. This also fixes the hug,
which today can only ever be right on one screen.

**P0-3. A global menu that real apps feed.**
The registrar otto-bar owns is the X11-era interface. On Wayland, Qt/KDE apps
publish their menu through **`org_kde_kwin_appmenu_manager`** (plasma-wayland-protocols):
the compositor hands each surface an appmenu object, the app sets
`(service_name, object_path)`, the shell reads it for the focused surface.
Nothing in Otto implements it, which is why zero `RegisterWindow` calls arrive.

- `otto`: implement `org_kde_kwin_appmenu_manager` + `org_kde_kwin_appmenu`,
  store the pair on the toplevel, expose it next to the app_id that
  `focus.rs` already reads.
- `otto-bar`: prefer that pair; keep the registrar for XWayland apps, where
  `_KDE_NET_WM_APPMENU_SERVICE_NAME` / `_OBJECT_PATH` and
  `_GTK_MENUBAR_OBJECT_PATH` still apply.
- GTK: `org.gtk.Menus` is a different wire format from `com.canonical.dbusmenu`
  and needs its own reader.
- **Do not rewrite this from scratch.** `dots/.config/quickshell/koompi/scripts/global-menu`
  is a working KOOMPI daemon that already resolves both formats, both X11
  atoms and the registrar. Port its resolution logic to Rust; it is the spec.
- Also replace the Wayland-native fallback in `appmenu.rs:83` —
  `regs.values().find(|r| r.service.contains(app_id))` matches a D-Bus unique
  name against an app_id and is a coincidence detector, not a lookup.

**P0-4. Apps follow the desktop's theme.**
The portal is right now; the toolkits are not listening. Set in the session:
`QT_QPA_PLATFORMTHEME=gtk3` or a Breeze-dark `kdeglobals`, GTK's
`gtk-application-prefer-dark-theme`, and an `XSETTINGS` answer for XWayland
(Otto already serves XSETTINGS for output scale — extend it). Verify with a
cold Dolphin, a cold GTK app and an XWayland app.

**P0-5. Find the dock.**
One eyeball answers it: if the dock is on screen but absent from `grim`, the
bug is that `zwlr_screencopy` composites only the primary plane and every
screenshot silently loses the dock, the app switcher and popups — all of which
Otto puts on their own KMS planes. If it is genuinely not drawn, that is a
different and more urgent bug. Fix follows the answer.

**P0-6. Compositor shortcuts must accept virtual-keyboard input.**
Two attempts with `wtype` did nothing. Route `zwp_virtual_keyboard_v1` events
through the same shortcut path as physical keys. This blocks automated testing
of every keybinding, which is why the hug-against-maximized check is still
unverified.

**P0-7. A polkit agent.**
`components/otto-auth-ui` already is "the authentication panel Otto shows when
it needs a password — shared by the greeter and the lock screen". A polkit
agent is that panel plus `org.freedesktop.PolicyKit1.AuthenticationAgent`. In
Rust, in the fork, reusing the panel. Not a QML bolt-on.

### P1 — the macOS-familiar surface

**P1-1. The KOOMPI star in the menu bar.**
Leading item, left of the app name, theme-aware — the same affordance as the
Hyprland session's `start-here.svg`. `otto-kit` already loads SVGs from
`components/otto-kit/resources/icons/`, so this is an asset plus a tint from
the bar's foreground colour, not new machinery. Clicking it opens the KOOMPI
menu (About, Settings, Lock, Log out, Sleep, Restart, Shut Down) — the Apple
menu's job, and the natural home for session actions the desktop has nowhere
else to put.

**P1-2. macOS pointer.**
`Bibata-Modern-Classic` is a Bibata cursor, not a Mac one. `Mkos-Big-Sur*` is
installed on this box but ships **no `cursors/` directory** — it is an icon
theme, not a cursor theme. So: package a real macOS-alike X-cursor theme
(`apple_cursor` / `macOS-Monterey` family), set `cursor_theme` and a
`cursor_size`, and make sure it reaches XWayland (`XCURSOR_THEME`/`XCURSOR_SIZE`),
the greeter and the lock screen. Pair with G below so GTK4 asks the portal and
gets the same answer.

**P1-3. Finish the Settings portal backend.** *(G)*
Add `org.gnome.desktop.interface.cursor-theme`, `cursor-size`, `font-name`, and
`org.freedesktop.appearance.accent-color`. Small, self-contained, upstreamable,
and it is what makes P1-2 stick for GTK4 apps.

**P1-4. Wallpaper.** *(F)*
Point `background_image` at `/usr/share/backgrounds/koompi`, pick the KOOMPI
default, and check the workspace-switch animation still reads well against a
photo rather than a flat colour.

**P1-5. Window frames in the desktop's colours.** *(C, second half)*
Otto's SSD titlebars must take the same scheme as the bar, and the corner
radius must match `WINDOW_CORNER_RADIUS = 18`. A light titlebar on a dark
window is the most visible "this is not macOS" tell on screen right now.

**P1-6. Icon theme resolution.** *(I)*
Otto matching on `index.theme`'s `Name=` and not following `Inherits=` is the
same fault the dock icon sweep already worked around. Fix it once, properly,
in the theme lookup: match by directory, follow `Inherits=`, fall through to
hicolor. Then `icon_theme` can name Breeze Plus and mean it.

**P1-7. Screenshot UI.** *(J, upstream's own "still to come")*
Region, window and full-screen, bound to the keys a Mac user expects
(Shift+Cmd+3/4 → `Logo+Shift+3/4`), landing in `~/Pictures/Screenshots` and on
the clipboard. Upstream lists per-window capture and a screenshot UI as
planned, so this is a contribution, not a fork divergence.

### P2 — depth, after the desktop is honest

- **`ext-workspace-v1`.** Otto has workspaces in `src/workspaces/` and exposes
  no protocol, so no external shell can show them. Needed if the bar ever
  grows a workspace strip.
- **A global-shortcuts protocol**, for Super-hold and anything a client needs
  to grab.
- **Per-monitor dock.** Upstream says primary-only and lists "move Dock code
  out of compositor core" as planned. Contribute there rather than forking it.
- **Gesture continuity.** Make the three-finger workspace swipe and the
  four-finger pinch track the finger with rubber-banding and velocity-based
  completion, instead of firing at a threshold. This is most of what "feels
  like a Mac" actually is.
- **Control centre.** One panel for network, bluetooth, audio, brightness,
  night shift and display arrangement, replacing `nm-applet` in the tray.
  Large; do it once the above is stable.
- **Spotlight-class launcher.** Otto's app switcher already searches XDG
  metadata and icons; a launcher is that index plus a text field.
- **Mirroring** — upstream's list.

## 4. Test plan

Nested Otto (`otto --winit`) is fine for layout and animation and **useless**
for the things that broke here: portal routing, D-Bus name ownership, KMS
planes, multi-output, SNI. Those need the real session, every time.

**Per change, on the real session:**

1. `grim` the full screen; crop the bar, the bottom edge, and the region under
   test. Remember `grim` captures a screen *region*, not a window — anything
   overlapping lands in the shot.
2. Portal: `gdbus call … Settings.ReadAll '["org.freedesktop.appearance"]'` —
   the answer must contain `icon-theme` (otto answered) and not `contrast`
   (gtk answered).
3. Global menu: `dbus-monitor --session "interface='com.canonical.AppMenu.Registrar'"`
   plus the appmenu protocol in `WAYLAND_DEBUG=1`, while cold-starting Dolphin.
4. Tray: compare `RegisteredStatusNotifierItems` against the icons drawn.
5. Theme: cold-start one Qt, one GTK and one XWayland app after switching
   `theme_scheme`; all three must follow.

**Traps already paid for, do not re-learn:**

- `pkill -f "otto --winit"` matches the tool's own shell and kills the call
  mid-run. Use `pkill -x`.
- zsh does not word-split unquoted `$var`, so `set -- $GEOM` yields empty
  positionals.
- Restarting `otto-bar` by hand drops every menu registration the previous
  instance held — apps register once, at start. Re-launch the apps too, or the
  global-menu test lies.
- xdg-desktop-portal caches its backend choice at startup. After changing
  anything about backends, restart `xdg-desktop-portal.service` *and* confirm
  with the debug run: `G_MESSAGES_DEBUG=all /usr/lib/xdg-desktop-portal -v`
  prints which `.portal` won and why.
- `fc-match` never fails a family, it substitutes — `fc-match Inter` answers
  Noto Sans Khmer here, which has no Latin glyphs.

**Worth automating** (`koompi-desktop/tests/`): a session smoke test that
asserts the portal scheme, the bar count against the output count, the SNI
count, and that `otto-bar`, `otto-islands` and the polkit agent are alive. Ten
lines of shell that would have caught three of today's four blockers.
